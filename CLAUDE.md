# DinoBoard Design Principles

## Read onboarding before non-trivial work

Before doing any non-trivial work in this repo — adding a game, changing the framework, modifying the web frontend, touching the training pipeline, or fixing anything beyond a single-line bug — read `docs/VIBE_CODING_ONBOARDING.md` first. It contains hard rules, a per-task read-order routing table, and the framework's non-goals (e.g. combinatorial action explosion like DouDizhu, mixed-strategy equilibria like poker, long-history-dependent games like Hanabi — these cannot be patched in here). Read it before paraphrasing the user's request back, before asking clarifying questions, and before writing any code. This is mandatory, not a suggestion.

## Training Pipeline

- Training is config-driven: only `game.json` parameters, no code changes per training run.
- Self-play loss not decreasing is normal (opponent also gets stronger). Don't diagnose it as a problem.
- Latest model always moves forward, never rolls back. Best model is tracked independently.
- Eval must use the same compiled code as selfplay. If code changes between build and eval, results are meaningless.
- The entire selfplay pipeline (selfplay, eval, arena) runs in C++. Never write Python fallback or reimplementation of any game logic or search logic. If you find yourself writing Python code that "does what the C++ does but slower", stop — that's a bug. The correct fix is always to expose the needed C++ functionality through pybind11.

## No Fallbacks, No Silent Degradation

- Never write fallback logic that masks errors. If something fails, throw/raise immediately — don't return a default value that makes the caller think it succeeded.
- Every function that receives data from C++ must access fields with `dict["key"]`, not `dict.get("key", default)`. Missing fields are bugs; defaults hide them.
- ONNX model is mandatory for selfplay, arena, and eval. Empty `model_path` is always an error. There is no uniform-policy fallback.
- `evaluate()` failures must throw, never return false. A silent `return false` caused BUG-011 (weeks of wasted training).
- `catch (...) { return false; }` is banned. Re-throw with context so the caller sees the real error.
- If you're writing code that makes a broken system "still run", stop. The correct fix is to make the system not broken.

## AI Pipeline Independence from Game State

The AI decision pipeline — belief tracking, feature encoding, MCTS search — works solely from observation history. It NEVER reads ground truth's hidden fields. **This is not a convention the AI is asked to respect — it is structurally impossible for the AI to cheat**, because:

1. **The belief tracker interface physically cannot reach an `IGameState*`.** `init(perspective, initial_observation)` takes an `AnyMap`; `observe_public_event(actor, action, events)` takes an event stream. The only entry point through which a tracker can write to a state is `randomize_unseen(state, observer, rng)`, but that is the **write** side — filling viz=0 slots, not a read into truth.
2. **The observer never runs `do_action_fast` for hidden-info games.** A session's `apply_observation` does NOT replay the action through rules. It runs `state.begin_step_for_session_observe() → public_state_applier(state, public_snapshot) → tracker.observe_public_event(actor, action, events)`. The public projection comes wholesale from the GT-side `public_snapshot`; the hidden slots are not touched at all on the session — they keep whatever values were last written (initial seed, or the previous ply's leftovers). There is no path on which sampled-hidden inputs could miscompute a public field. Fully-public deterministic games (TicTacToe / Quoridor) do call `do_action_fast(seat, view_step_rng)` because they have no snapshot and no hidden slots — the result is identical to truth modulo perspective.
3. **Decision-side reads of session state never reach viz=0 slots.** The hash walk substitutes `kHiddenHashSentinel` for viz=0 slots; the encoder reads through `MaskedState` whose viz=0 slots are `kPlaceholder`; MCTS sims call `sim_tracker->randomize_unseen(sim_state, observer, sim_rng)` once at sim entry on a clone. Whatever values the session's own viz=0 slots happen to hold are unreachable from any of these paths — they are not "belief", not "truth", just unread bytes. `test_public_hash_excludes_internal_rng` (60-seed × 4-game sweep) is the structural guard: two sessions with different `session_rng` seeds must produce identical `state_hash_for_perspective` throughout the same observation trace.
4. **Selfplay, web, and API all use the same stack.** One AI session and one belief tracker per perspective. The truth state held by the GT runner is only used to advance the game and dispatch snapshots — it is never handed to MCTS. The MCTS root state is always the AI session state of the current acting player; the three paths share the engine, encoder, tracker, and root-determinization protocol. `test_api_mcts_policy_invariance` provides a Love-Letter-only **statistical** regression — argmax-mismatch ≤ 0.65 and avg-TV ≤ 0.40 vs selfplay over the same observation trace, with Splendor excluded for a known replay / `self_reserve_deck` issue and the Web binding not directly covered. A real info leak would push those metrics well past the thresholds; bit-exact symmetry is not asserted because the three paths use independent MCTS RNGs.

   **Selfplay-side concretization**: `selfplay_runner` / `arena_runner` / `heuristic_runner` hold one independent `IGameState` per seat (`per_seat_states[p]`). After truth advances via `do_action_fast` on `gt_rng`, the runner advances each seat's session via the same public-event protocol the API path uses. For hidden-info games: `seat.begin_step_for_session_observe() → public_state_applier(seat, public_snapshot) → tracker.observe_public_event(actor, action, events)`. For fully-public games (no `public_event_extractor` registered): `do_action_fast(seat, view_step_rng[p])` (the framework's `IGameRules` wrapper auto-bumps step_count_). MCTS / encoder / `legal_actions` for the acting player read `per_seat_states[player]`, never truth. Currently landed for TicTacToe / Quoridor / Azul / Splendor / LoveLetter. `test_selfplay_no_truth_in_ai_path` guards these five games. Coup has been removed from `games/manifest.json` and does not compile; its old sources remain in-tree for reference until a schema-driven rewrite of its tracker / private state lands.

Together these mean the AI sees exactly what a physical player would: the message stream, nothing more. A bug that wants to leak information must first find somewhere for truth to hide — and the four pillars above leave no such place.

**Architecture**:

- **Ground truth** advances the game (our C++ engine, an external API, or a physical tabletop). GT holds the complete state (including all hidden fields), advances via rules, draws true randomness, judges termination, and broadcasts `(actor, action_id, events, public_snapshot)` per ply per perspective.
- **Visibility is carried by schema + a viz tensor.** Each game declares per-field metadata in `games/<id>/<id>_visibility.cpp`: name + data shape + base viz tensor (`all_public` / `owner_only_first_axis` / `all_hidden` / etc.). The state's `viz_` has the same shape as each field plus a viewer axis — `viz[..., p] = 1` means player `p` can see the slot's truth right now. **Rules are the sole writer of viz**: `do_action_fast` maintains viz alongside business fields (flip via `reveal_slot` / Priest peek via `reveal_slot_to(viewer)` / slot-content swap via `reset_to_base`).

  **Public ≠ "every state member that isn't a hand."** Whether a slot is "public" is determined by its current `viz[..., perspective]`, set explicitly by rules during the ply. It **structurally excludes**:

  - **Internal RNG state.** This isn't even something to "remember to exclude from hash" — the only framework-level state fields are `step_count_` and `viz_`. **RNG is not on state, not in hash, not on the wire.** There are exactly three RNGs at runtime: `gt_rng` (held by the GT runner, full game), `session_rng` (one per AI session, full session lifetime), `sim_rng` (sim-local stack variable, one sim) — **none derived from another, none shared, each independently seeded by its caller**. Reseeding any one does not affect the others. This is the physical foundation for ISMCTS-side independence (`test_public_hash_excludes_internal_rng` guards this).
  - **Future hidden draws** that have not yet resolved into a public observation (slots whose schema base viz is not `all_public` and which rules have not explicitly revealed are viz=0 to the observer).

  Rule of thumb: if a field's visibility to some perspective cannot be described as "schema base viz + rules' explicit reveals," it doesn't belong on state. viz is **not** a monotonic accumulator — when slot contents are swapped, rules call `reset_to_base` (Love Letter play, Coup influence-slot replace); on the AI side the snapshot **wholesale replaces, not OR-merges**.
- **Trackers** maintain what a perspective player has learned through legal observation. Neither `init(perspective, AnyMap initial_observation)` nor `observe_public_event(actor, action, events)` takes an `IGameState*` — the tracker physically cannot peek at truth. Trackers are **optional**: fully public + deterministic games (TicTacToe / Quoridor) and public physical-randomness games (Azul) need not register one; information-asymmetric games (Love Letter / Splendor / Coup) register a tracker to carry `randomize_unseen` for sim entry.
- **`randomize_unseen(state, observer, rng)` contract**: fill every slot where `viz[..., observer]=0` with concrete values, such that the produced world's **public slots** (viz=1 to any perspective) depend only on the tracker's observation history — not on the input state's hidden contents, not on the caller's RNG. Replaying the same observation sequence yields a byte-equal MaskedState public part (`test_public_snapshot_round_trip` + `test_api_belief_matches_selfplay` guard this). Called in exactly one place: at every MCTS sim entry on a cloned `sim_tracker` for determinization (`engine/search/net_mcts.cpp`). The session itself NEVER calls `randomize_unseen` — viz=0 slots on the session are unread bytes, not a "belief sample".
- **API / web session state**: `apply_observation` does NOT touch viz=0 slots. The session's hash uses `kHiddenHashSentinel` for them, the encoder uses `kPlaceholder`, and MCTS sims sample fresh worlds at sim entry. Any new caller that reads `state.get_state_dict()`'s viz=0 fields is reading semantically-undefined leftovers — that's a contract violation, not a feature.
- **Snapshot / hash / encoder share the schema-driven walker.** `make_masked_state(state, schema, perspective)` walks in schema order; for each slot it checks `viz[..., perspective]`: 1 → copy truth, 0 → write `kPlaceholder`. Three consumers: snapshot serialization (mask=1 slots flow through `read_field_slot` into the `public_snapshot` `AnyMap` keyed by field name), hash (each slot's `hash_field_slot` mixed into the digest, placeholder mixes a fixed sentinel), encoder (`encode_with_masked` reads the MaskedState into a `vector<float>`; viz=0 slots always read placeholder — structurally cannot encode truth).

  Call shape — both sides use the acting player from `state.current_player()` as the perspective (the acting player is also the observer); **the difference is only in call count**:
  - **Inside a sim, hash and encoder share the same MaskedState object**: sim descent masks once per step (perspective = current node's acting player), hashes first to decide if it's a new node, encodes only if it is — both consume the same copy.
  - **GT-side snapshot** the framework produces one `public_snapshot` per viewer per ply (perspective = that viewer) via the walker — `viz::serialize_public` for all_public slots plus `viz::serialize_partial_reveals` for non-all_public slots that runtime viz reveals to that perspective (LL hand[owner], LL drawn_card after `reveal_slot_to(starter)`, Coup influence after lose-influence). Broadcast as part of the message.

  On receiving a wire snapshot the AI side **wholesale replaces** `session.state` 's public part — every viz=1 slot is reconstructed via `viz::apply_public` + `viz::apply_partial_reveals`; the partial-reveal applier first resets the receiver's runtime viz on every non-all_public field back to schema base, then re-applies the sidecar's reveals (mirroring truth-side `reset_to_base` calls that the receiver wouldn't otherwise see). Then `tracker.observe_public_event` runs. **No viz recomputation, no OR-merge, no `do_action_fast`, no per-ply `randomize_unseen` on the session.** The viz=0 slots are left untouched (sim entry resamples them on a clone). The game only implements per-slot typed value emission (`hash_field_slot` / `read_field_slot` / `write_field_slot` / `mask_field_slot`); the framework's walker provides the overall traversal — there are no truth-sync patch events and no game-specific extractor / applier classes for the public part.
- **Per-perspective trackers in every path**: selfplay, arena, web, and API all allocate one tracker per perspective at game start, init once, and feed every public event to every tracker. The MCTS for the acting player uses that perspective's tracker, which has accumulated the full observation history for that seat. There is no per-ply re-init of a shared tracker.
- **MCTS** uses root determinization: each sim clones a `sim_tracker` (the session's tracker is never written into by sims), then calls `sim_tracker.randomize_unseen(sim_state, root.current_player(), sim_rng)` to fill the viz=0 slots. The tracker fixes certainties (e.g. opp hand revealed by a Priest peek) and samples the remaining unseen pool per its policy (uniform for simple cases; heuristic-weighted in bluff-heavy games like Coup, where claim/challenge history biases the opp role priors). After sampling, descent is fully deterministic in that world — the same `sim_rng` carries `randomize_unseen` and every `do_action_fast` along descent. Inside the sim, `sim_tracker` also calls `observe_public_event` on public events; sim_tracker is discarded with sim_state at the end of the sim.
- **MCTS node hashing** uses `state_hash_for_perspective(state.current_player())` — each decision node is keyed by the acting player's information set. Underneath, this is a schema-order walk of the FULL slot set (visible + hidden) plus `step_count`. The framework owns slot structure: per slot it first mixes `(field_pos, idx[])`, then dispatches the value mix — visible (viz=1) → game's `hash_field_slot` mixes only the value, hidden (viz=0) → fixed `kHiddenHashSentinel`. Games never mix `idx` themselves; that's the framework's job (BUG-037 postmortem — value-only mixes collide on multiset-equal worlds with different index sets). **No off-schema escape hatch**: every piece of state that participates in DAG node identity must be a schema slot. Variable-length structures get expressed as fixed-shape count arrays (multisets), with any visual ordering reconstructed client-side from the action stream; the previous `hash_extra_state_fields` hook has been removed at the framework level so future games cannot fall into the trap. This forms a **DAG** (transpositions reached through different paths share nodes via the global `hash → node_index` table). Tracker contents do **not** enter the hash — the same MaskedState must hash equally; nodes can't be split by tracker cache differences.
- **DAG acyclicity** is guaranteed structurally by `IGameState::step_count_` — a framework counter auto-bumped by the `IGameRules` wrappers (`do_action_fast` / `do_action_deterministic` pre-increment, `undo_action` post-decrement) and folded into the hash. No two states share a hash unless their step counts match; parent → child always increases step, hence **structurally acyclic**. The `step_count_` field is protected with `friend class IGameRules`, so games physically cannot mis-maintain it.
- **UCB** uses UCT2 (DAG-aware): the `sqrt(...)` numerator uses the visit count of the specific incoming edge traversed in this sim, not the DAG node's global visit count. Avoids the over-exploration bias from aggregating multiple incoming edges (Childs, Brodeur, Kocsis 2008).
- **Opponent-node selection (`opponent_selection`)**: at non-root opponent decision nodes ISMCTS can either run the same PUCT bandit (default `"puct"`) or replace it with a multinomial sample from the policy head's frozen prior (`"prior"`, Smooth-UCT style). Frozen-prior mitigates ISMCTS strategy fusion / opponent-omniscience — particularly for bluff-heavy hidden-info games (Love Letter / Coup) where bandit-driven opponents become artificially clairvoyant across determinizations. The acting player's own root selection is **always** PUCT regardless of mode (the `cur_idx != 0` guard in `engine/search/net_mcts.cpp`); switching that would drop bandit on the player who matters. Configured per-profile: `game.json mcts_profiles.<selfplay|arena|eval>.opponent_selection` and `web.json mcts_profiles.<web_expert|web_casual|analysis>.opponent_selection`; the `analysis` profile is set to `"puct"` so cross-difficulty drop-score / smart-hint stay self-consistent. The REST AI API never accepts it as a wire field — it is server-resolved from the `web_expert` profile.
- **Encoder**: input surface = MaskedState + tracker. The interface signatures lock `const MaskedState&` (`IFeatureEncoder::encode_public/encode_private`, `IPolicyValueEvaluator::evaluate`), so viz=0 slots are read as placeholder — no need to query viz, no need for an `is_visible_to` helper. Forgetting to branch on placeholder at worst emits wrong placeholder features; **truth never leaks**. Tracker-provided features are public derivations (e.g. Coup claim history, Splendor multiset stats) — public aggregates that don't carry per-perspective private information.

**Validation** (mandatory for every game, enforced in CI):

- `tests/framework/test_ai_api_separation.py::test_full_game_via_api` — parametrized over `FRAMEWORK_GAMES` (quoridor + azul + loveletter), the fixed three-game carrier. The API carries no state fields in/out; the AI drives a full game from observations alone. Per-game acceptance for non-carrier games lives in `tests/<game>/test_checklist.py`.
- `tests/framework/test_api_belief_matches_selfplay.py` — currently parametrized over `GAMES_WITH_EVENT_PROTOCOL = ["loveletter"]` only (Splendor / Coup belief checks live in their own checklists; capability-driven enrolment for tracker games is a future cleanup). AI session seeded differently from GT must yield identical belief, public state, and legal actions after the same observation stream.
- `tests/framework/test_api_mcts_policy_invariance.py` — `LEAK_SENSITIVE_GAMES = ["loveletter"]` only: statistical regression with argmax-mismatch rate ≤ 0.65 and avg TV distance ≤ 0.40 between selfplay and API MCTS visit distributions on the same observation trace. Splendor is excluded for a known replay / `self_reserve_deck` interleave issue; the Web binding is not directly covered. Loose by design (independent MCTS RNGs make exact agreement impossible); a real info leak would blow past these thresholds.
- `tests/framework/test_encoder_respects_hash_scope.py` — parametrized over `games_with_capability("hidden_info")` (manifest-driven). Encoder output must be bit-equal when opp private changes but the acting player's viz=1 slots stay the same.
- `tests/framework/test_public_hash_excludes_internal_rng.py` — parametrized over `games_with_capability("hidden_info", "snapshot")` (manifest-driven; currently 3 games — Splendor / Love Letter / Azul, plus Coup whenever it returns to `enabled=true`). 60-seed sweep: two API sessions with different `session_rng` seeds must produce identical `state_hash_for_perspective` throughout the same observation trace. This is the structural guard that decision-side reads do not reach session viz=0 contents — even if those bytes diverge between seeds (and they do, since rules' starting seed differs), the hash must not.
- `tests/framework/test_public_snapshot_round_trip.py` — parametrized over `games_with_capability("snapshot")` (manifest-driven). For every snapshot-path game, every ply: truth → `make_masked_state` → wire snapshot → observer session → apply snapshot, then the observer's `state_hash_for_perspective(own)` must be bit-equal to truth's. New public fields that miss schema / `read_field_slot` / `write_field_slot` updates are caught immediately.
- `tests/framework/test_dag_reuse.py` (file is `test_dag_reuse.py`; the historical "test_dag_acyclic" name was never actually applied) — `TRANSPOSITION_PRONE_GAMES = ["tictactoe", "quoridor", "splendor", "loveletter"]` (hand-picked: games where transpositions actually arise often enough to be worth testing). No cycles in the MCTS DAG, asserted via step_count monotonicity.

**No chance nodes**: physical randomness (deck draws, dice) is handled entirely by root determinization — different sims sample different worlds; observer-distinguishable randomness automatically forks via hash differences, observer-indistinguishable randomness automatically merges via hash equality. The framework has no special chance-node machinery (NoPeek / traversal limiter / `chance_outcomes` / afterstate cap / `stochastic_detector`).

## Value Head / Multiplayer

- Value head outputs N-dimensional value (N = num_players), not scalar. Even 2-player games output 2 dims.
- Value output is perspective-relative, aligned with the encoder's feature rotation: `values[0]` = my value, `values[1]` = next player, etc.
- The ONNX evaluator rotates the N-dim output back to absolute player ordering for MCTS backup.
- `IStateValueModel::terminal_values()` must satisfy zero-sum: `sum(values) ≈ 0`. The network learns this from targets, not from architectural constraint.
- Training targets use `sample["z_values"]` (per-player vector) rotated to perspective order, not the scalar `sample["z"]`.
- `game_metadata(game_id)` returns `{num_players, action_space, feature_dim}` from C++ — always prefer this over hardcoded JSON values for variant-aware code.

**Legacy scalar value head compatibility (2-player only).** Older 2p models (`tictactoe`, `quoridor` 2p, `splendor` 2p, `azul` 2p, `loveletter` 2p, `coup` 2p) were trained with a `[1, 1]` scalar value head, where the single output is the perspective player's value in [-1, 1]. The full 2p AI chain — selfplay, eval, web gameplay (winrate pill), replay analysis, smart hints (drop-score) — must continue to load and run these models without retraining. Compatibility lives in exactly one place: `OnnxPolicyValueEvaluator::evaluate`'s `value_len == 1 && num_players == 2` branch (`engine/infer/onnx_policy_value_evaluator.cpp`), which expands the scalar `v` into `(v_perspective, -v_opponent)` by zero-sum and returns a length-2 `values` vector indistinguishable downstream from an N-dim model. Everything past the evaluator (MCTS leaf backup, `root_values`/`action_values` bindings, `pipeline.py` analysis) is dimension-agnostic and needs no scalar-aware code.

This compatibility does **not** extend to 3p/4p: `value_len == 1 && num_players > 2` throws — there is no zero-sum decomposition that pins individual seats, and silently broadcasting would violate "no silent degradation." When refactoring the value-output decoding path, the scalar 2p branch must be preserved or migrated explicitly; deleting it silently breaks every shipped 2p model.

## Game Architecture

- Engine is fully game-agnostic. All game-specific logic lives in the game's GameBundle registration.
- One game = state + rules + visibility + net_adapter + register + config/game.json + web frontend. `visibility.cpp` declares the schema (per-field name + data shape + base viz tensor) and is the single source of truth for hash / encoder / snapshot scope.
- **`games/manifest.json` is the single source of truth for which games are live.** The same file is consumed by CMake, `setup.py`, the engine's auto-registered set (`engine.available_games()`), the web `/api/games/available` endpoint, and the framework test-matrix helpers in `tests/conftest.py`. Per-entry schema: `{id, enabled (default true), framework_whitelist (default false), capabilities ([] of "hidden_info" | "snapshot" | "tracker"), sources}`. To temporarily disable a game (Coup is currently `enabled: false` while its schema-driven tracker rewrite is pending) flip the one boolean — sources stay on disk but every layer skips it. To add a game append one entry; framework tests auto-cover it based on its declared capabilities, no test-file edits required.

## do_action_fast vs do_action_deterministic — undo support split

Two action-application entry points exist on `IGameRules`. They differ only in which path supports undo:

- **`do_action_fast(state, action, rng)`** — used by MCTS, selfplay, arena, and the web/API session. **Does NOT support undo.** Callers always discard the state after the simulation/episode/move. Rules implementations MUST NOT push to `undo_stack` here, MUST NOT snapshot `viz_` here, and MUST NOT do any other "save state for restore" work. Cloning state on the hot path (sims fire millions of times) for an undo that never happens is pure waste. The `UndoToken` returned is a vestige of the shared signature with `do_action_deterministic`; for `fast` it carries no obligation.
- **`do_action_deterministic(state, action)`** — used by the tail solver. **Supports undo via `undo_action`.** The solver does alpha-beta on the same state object via `do_action_deterministic` → recurse → `undo_action`. This path freezes any RNG-dependent draws (e.g. Splendor's `forced_draw_override = -2`) so the move is reproducible without a runner-owned RNG. Rules implementations DO push to `undo_stack` here, MUST snapshot anything they mutate (`persistent`, `viz_`, etc.) so `undo_action` can restore atomically.

If you find yourself adding undo-stack pushes to `do_action_fast`, stop — that's the bug. The cure is to remove them, not to mirror them in undo_action. The two existing callers of `undo_action` are both inside `engine/search/tail_solver.cpp`; they are paired with `do_action_deterministic`, never with `do_action_fast`. Don't break this invariant.

## Web Frontend Design

**Before touching any web frontend code — new game or modification — read `docs/guide/WEB_DESIGN_PRINCIPLES.md` and follow it. It is mandatory, not a style suggestion.** When you design a new game frontend, update the doc if you discover a new principle worth codifying for the next game; don't carry the lesson only in your head.

Full visual/interaction guide: `docs/guide/WEB_DESIGN_PRINCIPLES.md`.

- Web frontend is mandatory. It is the primary interface for players to play and for the developer to verify training results.
- Actions must NOT be mapped naively to individual buttons. Design interactions as the player would naturally play the physical game.
- Spatial anchoring: fixed game regions must have fixed screen positions and sizes. Never let a container shrink or shift when its contents change.
- Every action (human or AI) must have animated transitions via `describeTransition`. No instant state jumps.
- Visual clarity: sufficient color contrast, clear current-player indicator, hover feedback on interactive elements.
- Never hold a global lock (mutex, SQLite write lock, etc.) while running heavy computation (MCTS search, batch inference). Heavy work goes to a thread pool; locks are session-scoped and held only for state reads/writes.
- The Python GIL counts as a global lock. Any pybind11 binding that performs meaningful C++ work (MCTS, ONNX loading/inference, batch encoding) MUST wrap that work in `py::gil_scoped_release`. Without it, offloading the call to a ThreadPoolExecutor does nothing — the worker thread acquires the GIL for the entire C++ call and stalls every other Python thread, including the uvicorn request loop, causing the UI to freeze for seconds per move.
